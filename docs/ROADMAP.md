# NextBoard — feature parity roadmap (inspired by Symvibe)

Feature IDs A1…G1 and blocks P1…P14 refer to an internal feature inventory that is not in this repo. The visual design stays [DESIGN.md](DESIGN.md) (NextBoard Glass); Symvibe's look, branding and text are not copied.

**Not taken:** subscription & credits (F5), macOS-specific installation (A1), the iCloud banner, Quick Look/Finder, the native WebKit inspector (B19, replaced by a log card), a cloud-based planner & TTS (replaced by the user's own local CLI / Web Speech API).

**The agentless rule still applies** to SSH machines: install nothing and change no config on the target server. Questions that are still open are in [PROJECT.md §14](PROJECT.md).

## Phase 4 — Project & multi-tile board foundation *(done: hub, web, Android)*

| Block | Feature |
|---|---|
| P1 Project/Workspace | B5 project home screen (machine + path, git branch), B6 workspace tabs, sessions tied to a workspace, migration of the old `board.json` |
| Board v2 | a board document per workspace based on **ops** (live sync between clients), B7 `.prev` + hourly snapshots (24) + archive |
| Interaction | B1 navigation (zoom 20–300 %), B2 selection/marquee/clipboard/duplicate/undo-redo 80 steps/guides, B3 left rail (tools), right rail (insert), right-click menus for the canvas & nodes, B4 single-letter keys |
| Tiles | B9 sticky notes & text, B10 checklist, B11 kanban, B12 calendar, B13 shapes/lines/arrows + inspector (rough.js), B14 pen & eraser (perfect-freehand), B15 images + markup editor, B16 file cards (code snapshot, live markdown, file, folder) |
| P10 Exec & file API | stat/read/raw/write (local; SSH through the SFTP subsystem, read-only exec fallback) |
| Assets | a hub blob store for pasted/uploaded images |
| Clients | Full web; Android: navigation project → workspace → session |

## Phase 5 — Agents & status *(done: hub, web, Android; contract: [API-agents.md](API-agents.md), CLI verification results in §20)*

Includes the **E1 hidden CLI runner** (brought forward from Phase 7 because the planner, handoff, loop and memory in Phase 6 need it; contract in [API-studio.md](API-studio.md) §E1).

C1 console name (handle) & header, C2 spawn entry points, **C3/C11 WORKING / NEEDS YOU / READY status** (P3 VT screen model on the hub, P4 status engine, local hooks + per-launch injection when verified, a fallback that recognizes prompts on the screen), P5 transcript reader, C5 output viewer, C7 agent catalog + detection, C8 Yolo, C9 custom agents, C10 exact resume (conversation picker), C4 exit behavior, P13 notifications to Android when an agent needs input, the "needs you" chip + the `N` key.

## Phase 6 — Orchestration *(done: hub, web, Android; contract: [API-orchestration.md](API-orchestration.md))*

D1–D4 command bar (+ @mention, a thread per project, local parser), D6 delivery engine (paste + Return with a guard), D7–D8 dividing work & confirmation, D5 optional planner via a local headless CLI (`claude -p`, the user's plan — not cloud), D10 orchestrator card, D14 groups/teams + roles, D15 team report, D16 Mission Map, D17 pause/resume, D18 handoff, D19 forward, D20 loop (cron / idle / output pattern + goal check), D21 project memory, B8 layout templates.

## Phase 7 — Web, Git, Studios, Usage, Voice *(done: hub, web, Android, desktop; contract: [API-studio.md](API-studio.md))*

The usage check uses one fixed temp path per machine (`/tmp/nb-usage-<uid>`), recreated and then deleted every time, so that Claude Code records only one trust entry.

B17 web tile through the hub's preview proxy (local / SSH `direct-tcpip`), B18 automatic localhost preview, B19 console/network log card, B20–B22 Git panel + GitHub publish (`gh`) + branch card, E1 hidden CLI runner, E2 Documents (PDF), E3 Diagrams (landing as shapes), E4 Code studio, E5 Markdown studio + link graph, E6 Skills, F1 CLI login profiles, F2 usage pill, F3 reset chime, F4 token chart, D11–D13 voice (push-to-talk, local voice reply, dictation) via Web Speech API / Android SpeechRecognizer, settings & shortcut rebinding.

## Phase 8 — Desktop apps on the board *(done: hub, web; contract: [API-gui.md](API-gui.md))*

GUI apps on This PC (Chrome, VS Code and others) show in a tile through a headless compositor per app (sway + wayvnc, with Xtigervnc + openbox as a fallback) and noVNC, with AV1 or H.264 from the GPU for large motion, and sound per app. This PC only; SSH machines stay agentless. Android and desktop follow, per decision 8.

### Initial verification of CLI flags (This PC, 2026-10-28)

- **Claude Code 2.1.312:** `--settings <file-or-json>` accepts a JSON string → hooks can be injected per launch without writing `~/.claude/settings.json`. `--session-id <uuid>` → the hub decides the conversation ID (exact resume with `--resume <uuid>`, the transcript path can be computed). `--bare` turns hooks off (do not use it for interactive sessions).
- **Codex 0.163.0:** `-c key=value` overrides `~/.codex/config.toml` per launch (candidate `-c notify=[…]`); `resume --last` / picker.
- **Not verified yet (Phase 5 task):** that hooks from `--settings` are really called in interactive mode; whether the hook process has access to `/dev/tty` (an option for an event channel without a network: the hook writes an OSC escape to the TTY, which the hub reads; in tmux this needs `allow-passthrough` per session); an alternative channel: an SSH reverse port-forward from the hub's connection. Test with a minimal prompt, because it uses the user's plan.
